# Running on AapStack (OwnDatabase)

AapStack is Supabase-compatible (`@supabase/supabase-js` works unchanged), with four differences this app handles:

| | Supabase | AapStack | What this repo does |
|---|---|---|---|
| Schema | `public` | one schema per project (`project_remotejobs`) | `aapstack/migrations/` = the same migrations without `public.`, generated by `scripts/aapstack/convert-migrations.ts` |
| New-user trigger | trigger on `auth.users` creates the profile | projects can't add triggers to the shared `auth.users` | `bind_device()` creates the profile at first sign-in (works on both) |
| Functions | Deno Edge Functions | Node functions (`export default async function (req)`) | `aapstack/functions/sync-*.mjs`, one bundled file per source (`scripts/aapstack/build-functions.ts`); only callers with role `service_role` (cron, the admin button) may run them |
| Schedules | `pg_cron` + `pg_net` (`supabase/cron.sql`) | AapStack cron jobs (`function.invoke`, `sql.run`) | created by the deploy script with the same times |

Tested locally against an imitation of an AapStack project (own schema, restricted owner role, shared `auth.users`, extensions in `public`): `npm run test:aapstack`.

## Connect the app

`.env.local`:

```
NEXT_PUBLIC_SUPABASE_URL=https://aapstack.tech/p/<project id>
NEXT_PUBLIC_SUPABASE_ANON_KEY=odb_anon_…
SUPABASE_SERVICE_ROLE_KEY=odb_svc_…        # server only — never in NEXT_PUBLIC_*
```

## Deploy the database, functions and schedules

1. AapStack dashboard → **Access tokens** → create a token (or `odb tokens create deploy --days 90`). Add `ODB_TOKEN=odb_pat_…` to `.env.local`.
2. `npm run aapstack:build` (regenerates migrations + function bundles; already committed).
3. `npm run aapstack:deploy -- --dry-run` → tries the first pending migration and rolls it back.
4. `npm run aapstack:deploy` → enables `pg_trgm` + `unaccent`, applies the migrations, stores `SUPABASE_SERVICE_ROLE_KEY` (and any source keys) as function secrets, deploys the 14 sync functions + embed-jobs (smart search, see docs/AI.md) and creates the 18 cron jobs. Safe to re-run.

Alternative for migrations: AapStack SQL editor with `aapstack/ALL_MIGRATIONS.sql`, or the `odb` CLI (`odb db push <project id>` with `odb/migrations` = `aapstack/migrations`).

## Phone sign-in (OTP)
Dashboard → **Authentication → Settings → Phone (SMS)**: enable it, choose the SMS provider (Twilio, or **Webhook** for MSG91 / Gupshup), and set the template so Android fills the code in automatically:

```
Your Mana Kosamu code is {{code}}. Do not share it.

@your-domain.com #{{code}}
```

Add a test number (e.g. `+919999999999=123456`) for trying it without SMS. Ask the platform admin to set `SMS_DEFAULT_COUNTRY_CODE=91` (the app already sends +91 numbers).

## First admin
Sign in once on the site (this creates your profile), then in the SQL editor:
`update profiles set role = 'admin' where phone = '+91XXXXXXXXXX';`

## Notes
- Function limit is 60 s per run; each sync uses at most one page burst per source, well within it.
- `supabase/` stays the source of truth: edit migrations there, then `npm run aapstack:build`.
